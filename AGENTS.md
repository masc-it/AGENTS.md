# Rules

Before starting some work, make sure to read the rule files relevant to the task at hand.
It's important you keep in mind the user's preferences.

## Coding

- For any code change, read [`rules/coding/general.md`](rules/coding/general.md).
- For bug investigation or fixes, also read [`rules/coding/bug-fixes.md`](rules/coding/bug-fixes.md).
- For Python work, also read [`rules/coding/python/tooling.md`](rules/coding/python/tooling.md).
- For TypeScript, Svelte, or SvelteKit work, also read [`rules/coding/ts/svelte.md`](rules/coding/ts/svelte.md).
- For Tailwind, HTMX, or web UI work, also read [`rules/coding/web/ui.md`](rules/coding/web/ui.md).
- For SQL or database work, also read [`rules/coding/sql/queries.md`](rules/coding/sql/queries.md).

## Documentation

- For documentation or user-facing technical prose, read [`rules/docs/writing.md`](rules/docs/writing.md).
- For implementation plans, specifications, or task documents, also read [`rules/docs/work-plans.md`](rules/docs/work-plans.md).

Read every applicable file when a task spans multiple areas.
