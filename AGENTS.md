# Rules

Before starting some work, make sure to read the rule files relevant to the task at hand.
It's important you keep in mind the user's preferences.

For relevant domain context, consult [`domain-knowledge/`](domain-knowledge/), a git-ignored folder of local references; symlinks point to original files, so edits affect their source locations.

## Behaviour

- In every session, read and follow [`rules/behaviour/sessions.md`](rules/behaviour/sessions.md).
- In every session, read and follow [`rules/docs/writing.md`](rules/docs/writing.md) for all prose, including chat replies.

## Coding

- For any code change: [`rules/coding/general.md`](rules/coding/general.md).
- For bug investigation or fixes: [`rules/coding/bug-fixes.md`](rules/coding/bug-fixes.md).
- For Python work: [`rules/coding/python/tooling.md`](rules/coding/python/tooling.md).
- For TypeScript, Svelte, or SvelteKit work: [`rules/coding/ts/svelte.md`](rules/coding/ts/svelte.md).
- For Tailwind, HTMX, or web UI work: [`rules/coding/web/ui.md`](rules/coding/web/ui.md).
- For SQL or database work: [`rules/coding/sql/queries.md`](rules/coding/sql/queries.md).

## Git

- When the user mentions PRs, releases, tags, or related GitHub work: [`rules/git/github.md`](rules/git/github.md).

## Writing

- For implementation plans, specifications, or task documents: [`rules/docs/work-plans.md`](rules/docs/work-plans.md).

Read every applicable file when a task spans multiple areas.
